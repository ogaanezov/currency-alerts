# Currency Alerts

Сервис для оповещений о курсах валют: собирает курсы из внешнего API и уведомляет,
когда курс пересекает заданный порог.

Раз в час приложение получает курсы EUR, GBP, AMD, GEL и RUB к доллару из Open Exchange Rates,
сохраняет их в базу PostgreSQL и проверяет правила: при пересечении порога создаётся
уведомление, один раз на пересечение.

В веб-интерфейсе: текущие курсы, конвертер валют (сумма сразу во всех валютах), график курса,
нарисованные купюры каждой валюты, правила (добавить и удалить) и уведомления.
Есть светлая и тёмная тема, переключатель в правом верхнем углу. Всё это доступно и через REST API.

Технологии: Java 25, Spring Boot 4, PostgreSQL 18, Flyway, интерфейс на TypeScript (Vite, Chart.js).

## Быстрый запуск

Нужен только запущенный Docker Desktop. Проверить: `docker info`.

Для сбора курсов нужен ключ Open Exchange Rates (App ID), бесплатный тариф:
https://openexchangerates.org/signup. Без ключа приложение работает, но новые курсы не собирает.

Из корня проекта ввести ключ. Он не отображается при вводе и не попадает в историю команд:

```bash
read -s "OXR_APP_ID?App ID: "
export OXR_APP_ID
```

Затем в той же вкладке терминала собрать и запустить базу и приложение:

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. Когда в логе появится `Started CurrencyAlertsApplication`,
открыть http://localhost:8080.

Остановить: `Ctrl+C`, затем `docker compose down`. Данные базы сохранятся до следующего запуска.

Ключ живёт только в текущей вкладке терминала. Никогда не добавляйте ключ в файлы проекта.

### Открыть с телефона

`localhost` на телефоне означает сам телефон, поэтому ссылка http://localhost:8080 там не откроется.
Телефон и компьютер должны быть в одной Wi-Fi сети. Запустить приложение так, чтобы оно
было доступно в сети:

```bash
APP_HOST=0.0.0.0 docker compose up --build
```

Узнать адрес компьютера в сети (macOS):

```bash
ipconfig getifaddr en0
```

На телефоне открыть `http://<этот адрес>:8080`, например `http://192.168.1.10:8080`.
Если macOS спросит, разрешить ли входящие подключения, — разрешить.

Если сайт открывают другие люди, задайте ключ владельца (см. ниже), иначе любой сможет
менять правила.

### Ключ владельца

Смотреть курсы, конвертер, купюры, правила и уведомления может любой. Создавать и удалять
правила — только владелец. Для этого при запуске задаётся ключ владельца в переменной
`ADMIN_TOKEN`. Ввести его, как и ключ API, в той же вкладке перед запуском:

```bash
read -s "ADMIN_TOKEN?Ключ владельца: "
export ADMIN_TOKEN
```

На сайте в разделе «Правила» нажать «Я владелец» и ввести этот ключ: он запомнится в этом
браузере. Кнопка «Выйти» удаляет его из браузера.

Если `ADMIN_TOKEN` не задан, менять правила может любой. Так удобно для локальной разработки.

## Запуск для разработки

Так изменения в коде видны без пересборки образа. Нужны Java 25 (`java -version`),
Node.js 22 или новее (`node -v`) и Docker. Maven отдельно ставить не нужно: он запускается через `./mvnw`.

1. Только база данных:

   ```bash
   docker compose up -d postgres
   ```

2. Ввести ключ, как в быстром запуске, и в той же вкладке запустить бэкенд:

   ```bash
   ./mvnw spring-boot:run
   ```

   Проверить: `curl http://localhost:8080/health` должен ответить `{"status":"UP"}`.

3. В другой вкладке запустить интерфейс (`npm install` нужен только в первый раз):

   ```bash
   cd ui
   npm install
   npm run dev
   ```

   Открыть http://localhost:5173. Запросы `/api` Vite передаёт бэкенду на порт 8080,
   изменения в `ui/src` видны сразу.

Остановить: `Ctrl+C` в каждой вкладке, затем `docker compose down`.

## Как устроен запуск в Docker

`Dockerfile` собирает образ в три шага: интерфейс (`npm run build`), затем бэкенд с собранным
интерфейсом в `static` (Spring Boot отдаёт его на `/`), затем лёгкий образ только с Java и jar.
`compose.yaml` запускает базу и приложение. Приложение ждёт, пока база будет готова,
и подключается к ней по имени сервиса `postgres`.

## REST API

Полное описание с возможностью отправить запрос прямо из браузера:
http://localhost:8080/swagger-ui.html (приложение должно быть запущено).

| Запрос | Что делает |
|---|---|
| `GET /api/rules` | Все правила |
| `POST /api/rules` | Создать правило |
| `DELETE /api/rules/{id}` | Удалить правило и его уведомления |
| `GET /api/rates/{base}/{quote}?limit=24` | История курса, сначала новые |
| `GET /api/notifications` | Все уведомления, сначала новые |
| `GET /api/convert?from=EUR&to=GBP&amount=100` | Перевести сумму по последним курсам |
| `GET /api/access` | Может ли этот запрос менять правила |

Пример: создать правило «сообщить, когда USD/EUR станет выше 0.95»:

```bash
curl -X POST http://localhost:8080/api/rules \
  -H 'Content-Type: application/json' \
  -d '{"base": "USD", "quote": "EUR", "direction": "ABOVE", "threshold": 0.95}'
```

Конвертер считает любую пару через доллар: например, EUR → GBP = (USD/GBP) / (USD/EUR).

При неверных данных API отвечает `400` и объясняет ошибку в поле `detail`.
Если задан `ADMIN_TOKEN`, запросы `POST` и `DELETE` нужно отправлять с заголовком
`X-Admin-Token`, иначе ответ `403`.

## Как запустить тесты

```bash
./mvnw test
```

Для тестов нужен запущенный Docker: они сами поднимают отдельную временную базу
через Testcontainers. Тесты также запускаются в GitHub Actions при каждом push.
