# План проекта Currency Alerts

Сервис раз в час получает курсы валют из внешнего API, сохраняет их историю
и уведомляет пользователя, когда курс пересекает заданный порог.

Пример правила: «сообщить, когда USD/EUR станет выше 0,95».

## Границы первой версии

Входит:

- несколько валютных пар;
- один пользователь, без регистрации и входа;
- уведомления внутри приложения (запись в базе и показ в UI).

Не входит (можно добавить позже):

- учётные записи пользователей;
- email и Telegram;
- развёртывание на сервере.

Ограничение: приложение работает локально. Пока компьютер выключен, курсы
не собираются и уведомлений нет, поэтому в истории возможны пропуски.

## Технологии

| Что | Выбор | Зачем |
|---|---|---|
| Язык | Java 25 (LTS) | Версия с долгой поддержкой |
| Фреймворк | Spring Boot | Самый распространённый выбор для бэкенда на Java |
| Сборка | Maven Wrapper | Не нужно ставить Maven отдельно |
| База данных | PostgreSQL в Docker | Настоящая база, которую легко запустить локально |
| Миграции | Flyway | Схема базы хранится в git и меняется управляемо |
| Тесты | JUnit, Testcontainers | Проверка логики и работы с настоящей базой |
| UI | TypeScript | Пишет нейросеть |

## Как работаем

На каждый этап:

1. Создать ветку от свежего `main`: `git switch main`, `git pull`,
   `git switch -c stage-N-название`.
2. Писать код самому или с подсказками нейросети. Если код написала нейросеть,
   разобраться в каждой строке.
3. Делать небольшие коммиты, каждый про одно изменение.
4. Попросить нейросеть сделать ревью и сравнить с best practices, исправить замечания.
5. Обновить документацию в `docs/`: в `docs/progress.md` записать, что сделано,
   какие решения приняты и что делать дальше. Новому чату или агенту достаточно
   прочитать этот файл и `PLAN.md`.
6. Открыть pull request и влить ветку в `main`.

Бэкенд пишем сами, UI отдаём нейросети.

## Проблемные места

Заранее известные риски. Список дополним замечаниями автора идеи.

| Проблема | Что делаем |
|---|---|
| Внешний API недоступен или исчерпан лимит | Таймауты, логирование, повтор на следующем запуске |
| Неточные вычисления | `BigDecimal`, а не `double` |
| Путаница с часовыми поясами | Хранить время в UTC |
| Дубли курсов | Уникальный индекс в базе |
| Повторные уведомления | Хранить состояние правила и срабатывать только при пересечении порога |
| Утечка API-ключа в публичный репозиторий | Переменные окружения, `.gitignore` |
| Исчерпание лимита из-за перезапусков | Проверять время прошлого сбора перед запросом |
| Пропуски, пока компьютер выключен | Принимаем для первой версии, сравнивать с последним известным курсом |
